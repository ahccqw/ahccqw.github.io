用 Hexo + Redefine 主题搭好博客之后，真正天天要打交道的就是「改哪儿」。这篇就把本站常用的修改点整理成一张速查表：想改什么、去哪个文件、改哪一段，照着抄就行。

先认识目录结构

记住一句话：配置改根目录的两个 _config*.yml，内容放 source/，public/ 永远不手改。

一、站点基础信息 → _config.yml

这里管的是整站级别的信息。

想改什么 字段
浏览器标签 / SEO 标题 title
站点描述（meta description） description
关键词、作者、语言、时区 keywords / author / language / timezone
正式网址、文章链接格式 url / permalink
首页每页文章数 index_generator.per_page、per_page
当前使用哪个主题 theme
部署仓库与分支 deploy.repo / deploy.branch

二、主题外观与内容 → _config.redefine.yml

这是日常最常改的文件。 原则是：只在根目录的 _config.redefine.yml 里写要覆盖的字段，不要动 node_modules/hexo-theme-redefine/_config.yml——后者是主题默认值，重装依赖后会还原，也会被前者覆盖。

想改什么 字段
首页显示的站点名 / 副标题 / 作者 / URL info.title / info.subtitle / info.author / info.url
站点图标 / logo / 头像 defaults.favicon / defaults.logo / defaults.avatar
主题主色、默认亮/暗 colors.primary / colors.default_mode
首页大标题、副标题、背景图、文字颜色 home_banner.title / home_banner.subtitle.text / home_banner.image / home_banner.text_color
首页社交图标链接 home_banner.social_links
顶部导航菜单 navbar.links
侧边栏、文章列表的日期/摘要/分类/标签 home.*
文章页样式（字号/行高/目录/代码块/版权） articles.*
评论系统 comment.system + comment.config
页脚（运行时间/统计/自定义文案/备案号） footer.*
访问量统计 / Google Analytics global.website_counter / global.google_analytics
自定义字体 global.fonts
注入自定义 HTML/CSS/JS inject.head / inject.footer

四、这些不要手动改

文件/目录 原因
public/ 生成产物，hexo generate 会重建
db.json Hexo 缓存，自动维护
package-lock.json npm 锁文件，交给 npm
.deploy_git/ 部署产物
node_modules/**/_config.yml 主题默认值，用 _config.redefine.yml 覆盖即可

五、常用命令

如果 package.json 里配了脚本，也可以用 npm run server / npm run build / npm run deploy。改完配置后如果预览没生效，先 hexo clean 再 hexo server。

六、一个特例：页脚署名

页脚那行「由 Hexo 驱动 · 主题 Redefine v2.9.0」是写死在主题模板里的：

删它属于「改模板」，不是改配置。注意 npm install 后会被还原。想长期保留，稳妥做法是把主题复制到 themes/redefine/ 作为本地主题再用（Hexo 会优先使用 themes/ 下的同名主题），或者用 postinstall 脚本自动打补丁。

以上就是本站的日常维护地图。真正高频的其实就两个文件：改站点信息看 _config.yml，改外观和开关看 _config.redefine.yml；内容则全部在 source/ 里。剩下的交给 hexo clean && hexo generate 就好。
